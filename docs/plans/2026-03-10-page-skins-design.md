# 产品页皮肤设置设计

日期：2026-03-10

## 背景

当前防伪页与通用页的视觉风格固定写在模板里，所有产品共用同一套页面外观。业务希望每个产品都能单独选择一套页面皮肤，并且防伪页与通用页共用该皮肤。

同时，这个配置不应放在“联系我们设置”里，而应作为一个独立入口，出现在产品导航栏 `联系我们设置` 后面。

## 目标

- 为每个产品新增独立的 `皮肤设置` 页面
- 同一产品的防伪页和通用页共用同一套皮肤
- 首批上线 4 套整风格皮肤，而不是只换颜色
- 皮肤设置页支持实时预览，最终点击保存才落库
- 未配置皮肤的老产品继续保持当前默认风格

## 非目标

- 不支持后台自由配色
- 不为防伪页和通用页分别选不同皮肤
- 不把每套皮肤拆成独立 HTML 模板

## 方案选择

### 方案 A：皮肤注册表 + 每产品选一个皮肤

推荐方案。

新增一个皮肤注册表，集中定义每套皮肤的名称、说明、缩略预览配色和页面样式变量。每个产品只保存一个 `skin_id`，公开页渲染时根据 `skin_id` 注入对应皮肤变量。

优点：

- 维护成本最低
- 后续新增第 5 套、第 6 套皮肤只需扩注册表
- 不会把现有页面逻辑拆碎

### 方案 B：每个皮肤一整套独立模板

不采用。

虽然视觉自由度高，但后续每改一次功能，所有模板都要同步维护，长期成本过高。

### 方案 C：每产品自定义样式参数

不采用。

灵活度太高，后台复杂，且很容易出现不协调的页面效果。

## 数据设计

继续使用 `PageContent.content_json` 保存产品级配置，不新增数据库表。

新增存储键：

- `product:{id}:skin_settings`

数据结构：

```json
{
  "skin_id": "classic_red"
}
```

兼容规则：

- 没有配置时默认使用 `classic_red`
- 非法 `skin_id` 也回退到 `classic_red`

## 皮肤注册表

首批预设 4 套皮肤：

- `classic_red`
  - 官方防伪感，延续当前经典红
- `black_gold`
  - 黑金金属感，偏高端礼盒
- `ocean_blue`
  - 科技清爽感，偏现代冷色
- `forest_green`
  - 深绿自然感，偏稳重品牌

每套皮肤定义：

- `id`
- `name`
- `description`
- `preview_colors`
- `css_vars`

其中 `css_vars` 至少覆盖：

- 页面背景
- 品牌头背景
- 卡片背景 / 边框 / 阴影 / 圆角
- 标题与正文颜色
- 按钮背景 / 边框 / 阴影
- 标签页、推荐区、内容块样式
- 提示框样式

## 后台交互

### 入口

在 [app/templates/admin/_product_tabs.html](/srv/anticounterfeit/app/templates/admin/_product_tabs.html) 中，在 `联系我们设置` 后面新增 `皮肤设置` 按钮。

### 页面

新增：

- 路由：`/admin/products/{product_id}/skin-settings`
- 模板：`admin/skin_settings_edit.html`

布局沿用当前编辑页模式：

- 左侧：4 张皮肤卡片 + 单选
- 右侧：两个手机预览
  - 防伪页预览
  - 通用页预览

交互规则：

- 选中某套皮肤后，右侧两个 iframe 立即切换到该皮肤
- 此时仅用于预览，不写库
- 点击保存后，才把 `skin_id` 落库

## 公开页渲染

### 数据读取

在 `public_pages.py` 中新增产品皮肤读取逻辑：

- 正常访问：读取产品已保存的 `skin_id`
- 预览模式：允许用查询参数 `skin_id` 临时覆盖

### 模板渲染

不复制模板，而是让 [app/templates/verify.html](/srv/anticounterfeit/app/templates/verify.html) 和 [app/templates/verify_generic.html](/srv/anticounterfeit/app/templates/verify_generic.html) 共享同一组皮肤变量约定。

模板中：

- `:root` 使用 `skin.css_vars`
- `body` 或根容器附加 `skin-{{ skin.id }}`
- 若有少数视觉差异需要条件控制，用少量 `skin.id` 分支，而不是整页复制

## 测试策略

### 后台测试

- 皮肤设置页存在并显示 4 套皮肤
- 保存后只影响当前产品
- 导航栏顺序正确，按钮在 `联系我们设置` 后面
- 预览 iframe URL 会带上当前选中的 `skin_id`

### 前台测试

- 防伪页按产品皮肤输出对应变量
- 通用页按同一产品皮肤输出对应变量
- `preview=1&skin_id=...` 能临时覆盖预览
- 未配置皮肤时回退 `classic_red`

## 风险与控制

- 页面样式目前直接写在模板中，改为皮肤变量时要控制改动范围，避免破坏现有显示逻辑
- 两个公开页模板有重复 CSS，需要保持皮肤变量命名一致
- iframe 实时预览需要依赖公开页 `preview=1` 查询覆盖，因此只在预览模式接受临时 `skin_id`

## 结论

采用“皮肤注册表 + 每产品保存一个 `skin_id` + 公开页预览临时覆盖”的方案，用最小的数据改动实现每产品独立皮肤，并保证后续扩展新皮肤时仍可持续维护。
